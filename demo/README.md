# PraiseTeam demo

The separate demo uses the regular Flutter screens and repositories with a
browser-local `DemoClient`. Build with `DEMO_MODE=true`; no Supabase, OAuth or
Firebase push initialization occurs. `DemoHttpClient` rejects any host except
its `.invalid` placeholder and never forwards HTTP. Realtime callbacks and
storage uploads also terminate locally.

- Prefilled fictional team, people, songs/versions, ten weekly services,
  rehearsals, assignments, notices, messages, a poll and sample annotation.
- A curated reference manifest lives in `app/assets/demo/reference.json`.
  Public song/video metadata reflects common worship preparation workflows.
  Names, conversations and schedules are synthetic. Private imported chat,
  photos, recordings, spreadsheets and original scores are not shipped.
- Original demonstration PDFs are generated by `demo/generate_charts.py`.
  They are explicitly labeled examples, not transcriptions of the songs.
- Changes persist in browser storage, reset on request, and refresh on a new
  team-calendar day or a changed seed. Each visitor has independent data.
- The live UI is a **single-device preview**. It does not invent connected
  participants. Real cross-device sync is demonstrated in the film instead.
- The Firebase Spark project `praiseteam-sg-demo` is separate from production.
  It uses static Hosting only, within the free quota. No extra Supabase project
  or paid billing plan is required. Free quota exhaustion can interrupt hosting.

## Build, test and publish

```sh
cd app
flutter pub get --enforce-lockfile
flutter test test/demo_test.dart
flutter build web --release --dart-define=DEMO_MODE=true --output=build/demo
cd ..
python3 e2e/spa_server.py app/build/demo 3001
# In another terminal:
node e2e/flow_demo.js
# Publish only the separate demo site; existing production stays unchanged:
scripts/deploy-demo.sh --skip-build
```

The browser flow checks navigation, mutations, reload persistence, visitor
isolation, setlist edits/publication, a real sample PDF, single-device presence,
chat/polls, reset, desktop/mobile layouts, and absence of cloud backend calls.

## Narrated product film

`demo/media/storyboard.json` is the Korean script. The output is a 1920×1080,
roughly three-minute landscape MP4 with synthesized Korean narration, subtitles,
animated title cards and real UI actions. Only the public, fictional script
is sent to the speech service. No original group-chat media is used.

Tools: FFmpeg with libx264/AAC, Python packages in `media/requirements.txt`,
Noto CJK fonts, Chrome and `npm ci --prefix e2e`. The film fixture requires the
existing **local** Supabase stack. It asserts the localhost endpoint, allocates
its own identities/rows/PDFs and removes those fixtures on completion or error.
It does not reset the local database or connect to production.

```sh
cd app
dart run tool/export_demo_data.dart
flutter build web --release --dart-define-from-file=env/local.json --output=build/video
cd ..
python3 e2e/spa_server.py app/build/video 3002
# In another terminal, with media/requirements.txt installed:
python demo/media/narrate.py
node demo/media/record.cjs
python demo/media/render.py
```

The live recording asserts two actual authenticated participants, remote page
following, a received cue and independent navigation after disabling follow.
The notes recording checks with a second authenticated account that private
ink is hidden and shared ink is visible. Captures and generated audio remain ignored under
`demo/media/work/`; finished MP4/VTT files go under ignored `output/demo/`.
The deployment script copies them to the separate demo's `/watch.html` tour.
Deployment requires the finished MP4, VTT and poster (render them or restore
the demo release assets into `output/demo/`). Generate the poster from any
finished frame with FFmpeg; its filename is `praiseteam-tour-poster.jpg`.

If the speech service is unavailable, a separate, explicitly marked silent
review can still be produced from existing captures:

```sh
python demo/media/preview.py
python demo/media/render.py --preview
```

This writes `output/demo/review/praiseteam-tour-ko-preview.mp4`. Its subtitle
timings are estimates for review. It leaves the production MP4, audio and
timing manifest intact and is never copied by the deployment script.
Normal rendering rejects a stale narration manifest after a script edit.
